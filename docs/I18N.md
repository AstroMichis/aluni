# Internationalization

English first (`default_locale :en`), Spanish available (`:es`). Every string a person can read goes through `t()`; the specs in `spec/i18n/` are the enforcement.

## Configuration

`config/application.rb` sets the locales, fallbacks and a glob load path so nested locale directories work. `config/environments/test.rb` has `raise_on_missing_translations = true`. `rails-i18n` supplies Spanish defaults (dates, errors).

## Files

```
config/locales/
  en/
    en.yml                    # app_name, meta, layouts, native_only, signups, platform, passkeys.errors, time/date/number formats
    en.activerecord.yml       # model and attribute names
    views/en.<area>.yml       # pages, sessions, registrations, passkeys, app, shared (+ web_push, push_permission), native_app
    mailers/                  # one file per mailer when mailers grow
  es/                         # the same tree, same keys
```

Keys nest under the view path so lazy lookup works: `t(".title")` in `app/views/sessions/new.html.erb` is `sessions.new.title`; in a controller action it is `<controller_path>.<action>.<key>`.

## Switching

`ApplicationController#switch_locale` wraps every action in `I18n.with_locale`. `extract_locale` order: URL `params[:locale]` (also written to the permanent `locale` cookie), the cookie, the signed-in person's `locale`, `Accept-Language`. `default_url_options` always adds the locale, so every link carries `/en/` or `/es/`. Routes wrap the site and the app in `scope "(:locale)", locale: /en|es/`; health, native shell endpoints, PWA files, API and webhooks stay outside. `GET /locale/:new_locale` (`PagesController#set_locale`) persists the choice (cookie and account) and goes back with the prefix swapped; `shared/_language_toggle.html.erb` renders plain links through `ApplicationHelper#localized_path`.

## Formats

`l(time, format: :short)` and `l(date, format: :long)` use the formats in `<locale>.yml`. Currency: `number.currency.format` is USD in both locales; store money as integer minor units or `decimal`, never Float. Pluralization and interpolation live in the locale files (`one:`/`other:`, `%{name}`).

## Specs

- `locale_parity_spec.rb`: the flattened key sets of `en` and `es` are identical (plural branches collapse); no em dash in any locale file.
- `no_boolean_keys_spec.rb`: no YAML key parses as a boolean or nil (`on`, `off`, `yes`, `no`, `true`, `false`, `null` unquoted).
- `core_copy_rules_spec.rb`: `app_name` is the one place the brand is written; views contain no hardcoded brand, no em dash and no visible text outside `t()`.

## Writing copy

Plain, warm, short. Spanish uses neutral `tú` forms (no regional voseo). No em dashes. The assistant is never called "AI" in copy unless the product decides otherwise. Add both locales in the same change.
